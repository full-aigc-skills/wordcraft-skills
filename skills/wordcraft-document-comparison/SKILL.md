# 文档修改核对

## 任务起点

先读取素材，确认交付用途、目标尺寸或时长、修改范围与必要格式。能从任务和素材确定的细节直接采用合理默认值；只询问会改变结果的缺失条件。

需要可见编辑器时交给 **wordcraft-editor** 技能。独立安装：`npx skills add full-aigc-skills/wordcraft-skills --skill wordcraft-editor`。当前新增技能为本地候选，发布前使用本地配套插件，不把此安装命令当作已发布证明。

## 执行步骤

1. 保留两版输入，按章节和段落建立对应。
2. 列出新增、删减和改写，单独检查数字、日期与专有名词。
3. 把纯格式变化与内容变化分开。
4. 输出变更清单和需确认事项。

## 工具落地

用 open_document/new_document 管理文档；get_text 核对、type_text 输入，其他编辑按实时工具列表；save_document 保存，render_page 检查排版。

先读取实际工具 schema，再填写参数；对象或文档 ID 使用返回值。查询到的命令必须在当前后端可用。保存前选择新输出路径，保留输入。需要的算法、格式或命令不存在时说明缺口，不能用相近名称冒充。

## 结果检查

- 段落移动不误报为内容丢失。
- 关键数字与结论变化被单独列出。
- 缺少修订模式时用对照表，不声称生成了原生修订记录。

对照用户目标检查实际内容，而不只检查进程退出码。局部编辑查看局部细节，版式任务查看整页，时间媒体查看起止与关键段。异常结果先检查当前工程，避免重复执行不可逆操作。

## 交付

返回可编辑工程、实际派生文件和简短说明：做了哪些修改、哪些步骤因当前能力未执行、需要用户判断的内容。只列真实存在且已经检查的文件。若用户随后返工，读取本次源工程并局部修改，保留已接受的内容。
