# 需求说明填写指南

适用输入：访谈记录、业务规则或产品需求草稿。

**内容规则：**需求、解决方案和未决问题分开；每项需求有编号和可观察验收条件。

| 字段 | 内容 | 填写提示 |
| --- | --- | --- |
| `title` | 文档标题（必填） | 按具体对象命名 |
| `document_date` | 文档日期（可待确认） | 不确定时待确认 |
| `author` | 编写人（可待确认） | 不推断责任归属 |
| `context` | 业务背景与用户（必填） | 说明服务对象、使用情境与当前问题 |
| `scope` | 本期范围与非目标（必填） | 明确包含和不包含的场景 |
| `rules` | 业务规则与约束（必填） | 列明确规则、权限、边界与依赖 |
| `quality` | 质量要求（必填） | 只记录有依据的性能、可用性和兼容目标 |
| `open_issues` | 待确认事项（必填） | 列出影响实施的未决问题 |
| `records` | 需求与验收条件（必填） | 二维字符串数组，按表头列顺序；未知单元格写待确认，不使用制表符或换行 |

## 使用方式

1. 读取输入，按本类型整理字段。先区分已有事实、建议、估算和待确认；不要把示例数据交付给用户。
2. 将字段写入JSON对象。表格`records`为二维字符串数组，列顺序为：编号、需求、验收条件、优先级。按实际条目增减行，不能用空行假装已有内容。
3. 已打开编辑器时，先编译参数JSON，再将steps逐条发送到该编辑器同一会话的实际命令工具；先确认是新建空文档。不要用独立CLI改变另一份文件并声称画面同步。
4. CLI新建文件时可使用脚本的--save和--pdf；本地已有wordcraft-cli才执行，不自动安装。
5. 有必填资料缺失时默认报出字段；明确生成不完整草稿可用--allow-incomplete，正文和表格显示待确认。状态READY_FOR_REVIEW只表示字段齐备，仍需内容与页面检查。

```text
python scripts/render_document_template.py --input 本次字段.json --output 本次步骤.json
python scripts/render_document_template.py --input 本次字段.json --output 本次步骤.json --save 新文档.docx --pdf 审阅稿.pdf
```

路径按当前安装技能目录解析；输入和输出使用实际路径，不拼接shell字符串。所有输出必须是不同且未占用的路径。CLI生成步骤在一个原生进程执行，保存后另行转PDF；脚本不提供既有文档修改或模板批量套用。

## 排版与交付

A4、常规页边距；标题为Heading 1，章节为Heading 2，正文回到Normal。末尾表格先逐行建立真实段落，仅扩选这些新增段落后转换成原生表格，并按页面宽度自适应、设置重复表头。模板不强制安装某商业字体；中文显示和打印分页以实际PDF检查。

用输入检查正文和每个单元格，确认没有残留示例、占位符或意外合并。篇幅长时逐页查看表格跨页、表头、断行和页边界。默认版式适合内部业务文档，不宣称公文、合同或行业格式认证。

[模板数据](../assets/template.json)和[虚构填写示例](../examples/input.json)均在当前技能内。示例只用于理解字段和回归，实际任务替换全部相关内容。
